02

Whitelist Layer — Instant Safe for Trusted Domains

Before any ML runs, the domain root is checked against a hardcoded whitelist of 500+ globally trusted sites (Alexa Top 500, Cisco Umbrella). If matched, the URL is instantly marked SAFE — this eliminates false positives for legitimate sites with long UTM tracking parameters like Udemy, Netflix, or Amazon.

def is_trusted(hostname: str) → bool: # Extract root domain: "www.udemy.com" → "udemy.com" root = _get_domain_root(hostname) return root in TRUSTED_DOMAINS # Example: Udemy with long UTM params url = "https://udemy.com/?utm_campaign=Brand&utm_source=..." # → is_trusted("udemy.com") = True → INSTANT SAFE ✓ # → ML model never even runs TRUSTED_DOMAINS = { "udemy.com", "google.com", "paypal.com", "github.com", "amazon.com", "netflix.com", # ... 500+ more domains }
03

Feature Extraction — 25 Numerical Signals

The URL is parsed and converted into 25 numbers that the ML model can understand. These cover structural patterns (length, dots, hyphens), semantic signals (suspicious keywords, brand names), entropy/randomness (DGA detection), and domain-level analysis. Every number captures a different "smell" of phishing.

from urllib.parse import urlparse import re, math from collections import Counter def extract_features(url: str) → list: parsed = urlparse(url) hostname = parsed.hostname.lower() path = parsed.path.lower() # Structural features url_length = len(url) # longer = more suspicious dot_count = url.count(".") # subdomain depth is_https = scheme == "https" # HTTPS ≠ safe! # NEW: DGA / entropy features (v5+) domain_entropy = _entropy(domain_body) is_random_domain = _is_gibberish(domain_body) subdomain_is_gibberish = _is_gibberish(longest_subdomain) longest_label_len = max(len(l) for l in hostname.split(".")) both_gibberish = subdomain_gibberish and domain_gibberish return [url_length, dot_count, has_at, has_hyphen, subdomain_count, is_https, path_length, ... domain_entropy, is_random_domain, subdomain_is_gibberish, longest_label_len, both_gibberish]
04

Random Forest — 300 Trees Vote on the Verdict

A Random Forest is an ensemble of 300 independent Decision Trees, each trained on a random subset of data and features. Every tree casts a vote (PHISH or SAFE), and the majority wins. This makes the model extremely robust — even if some trees are tricked, the majority overcomes it. The confidence score is simply the percentage of trees that voted PHISHING.

from sklearn.ensemble import RandomForestClassifier clf = RandomForestClassifier( n_estimators = 300, # 300 decision trees max_depth = 28, # each tree can go 28 levels deep class_weight = "balanced", # handles imbalanced data n_jobs = -1, # use all CPU cores random_state = 42 ) clf.fit(X_train, y_train) # Prediction = majority vote of 300 trees pred = clf.predict([features]) # 0=safe, 1=phish conf = clf.predict_proba([features])[0][1] # % trees voted phish # e.g. ourlzllc.com → 300/300 trees voted PHISH → 100% confidence
05

Flask API + Chrome Extension — Real-Time Detection

The trained model is saved as a .pkl file and served via a Flask REST API running locally at port 5000. The Chrome extension's background service worker intercepts every page navigation, sends the URL to the API, and receives a verdict within milliseconds. The background worker is used (not content scripts) to bypass mixed-content HTTPS restrictions.

# server.py — Flask API @app.route("/predict", methods=["POST"]) def predict(): url = request.json["url"] features = extract_features(url) # 25 numbers pred = clf.predict([features])[0] conf = clf.predict_proba([features])[0][1] return {"prediction": "phishing" if pred else "safe", "confidence": round(conf * 100, 1)} # background.js — Chrome Extension (MV3) // Routes around mixed-content restriction chrome.runtime.onMessage.addListener((msg, _, reply) => { if (msg.type === "CHECK_URL") { fetch("http://127.0.0.1:5000/predict", { method: "POST", body: JSON.stringify({url: msg.url}) }).then(r => r.json()).then(reply) } })

What the Model Looks At

Each URL is converted into 25 numbers. The importance bar shows how much each feature contributes to the final decision.

FEATURE 01
url_length
Total character count of the URL. Phishing URLs average 98 chars vs 39 for legit.
CORE
FEATURE 02
dot_count
Number of dots. More dots = deeper subdomain nesting (e.g. paypal.com.evil.tk).
CORE
FEATURE 03
has_at_symbol
@ in URL = redirect trick. paypal.com@evil.cc sends you to evil.cc not paypal.
CORE
FEATURE 04
has_hyphen
Hyphens in domain. paypal-secure.xyz uses hyphens to look legitimate.
CORE
FEATURE 05
subdomain_count
Number of subdomain levels above the root domain.
CORE
FEATURE 06
is_https
HTTPS does NOT mean safe — phishers get free SSL certs. Combined with other features to determine safety.
CORE
FEATURE 07
path_length
Length of the URL path. Phishing pages often have deep paths like /secure/verify/account.
CORE
FEATURE 08
query_length
Length of query parameters. Phishing: long tokens. Legit UTM params handled by whitelist.
CORE
FEATURE 09
has_ip_address
IP as hostname (e.g. http://192.168.1.1/login.php). No legit site uses raw IPs.
CORE
FEATURE 10
special_char_count
Count of %, =, &, #, ! in the URL. High count = encoded/obfuscated phishing URL.
CORE
FEATURE 11
double_slash_count
Extra // in path used to confuse URL parsers or redirect to attacker domain.
CORE
FEATURE 12
digit_count
Total digits in URL. Phishing URLs average 12 digits vs 1 for legit sites.
CORE
FEATURE 13
suspicious_kw_in_domain
Detects "crypto", "wallet", "defi", "verify", "recover" etc. inside the domain itself — not just path.
NEW v2
FEATURE 14
brand_in_domain
Brand name (paypal, amazon, coinbase) in a non-whitelisted domain. Classic spoof pattern.
NEW v2
FEATURE 15
free_tld
Uses a free/abused TLD: .tk, .ml, .ga, .xyz, .top, .click etc. 80%+ of PhishTank URLs use these.
NEW v2
FEATURE 16
domain_length
Total length of hostname. servcaccntwebapp...dtuiertgdfhfgdj.com = 48 chars. Way above normal.
NEW v2
FEATURE 17
domain_digit_ratio
Fraction of digits in the domain. High ratio = auto-generated domain like abc4x5k.com.
NEW v2
FEATURE 18
suspicious_kw_in_path
Full phrases like "wallet/connect", "airdrop/claim", "account/suspended" in path — strict matching to avoid false positives.
NEW v2
FEATURE 19
hyphen_count_domain
Total hyphens in full hostname. paypal-secure-verify-now.xyz has 3 hyphens = strong phishing signal.
NEW v2
FEATURE 20
brand_in_subdomain
Brand name in subdomain used to fool users: paypal.com.attacker.tk — paypal is only the subdomain.
NEW v2
FEATURE 21
domain_entropy
Shannon entropy of domain name. "google" = 2.58 (low). "dtuiertgdfhfgdj" = 3.19 (high = random).
NEW v4
FEATURE 22
is_random_domain
Binary flag: domain is gibberish (>70% consonants + high entropy). Catches ourlzllc.com, phishzqr.xyz.
NEW v4
FEATURE 23
subdomain_is_gibberish
Checks if the subdomain label itself is random. "servcaccntwebappaoiuhyswerdg" is pure DGA output.
NEW v5
FEATURE 24 ⭐ #1 MOST IMPORTANT
longest_label_len
Length of the longest DNS label. Real sites use "www","mail","api" (3-6 chars). DGA uses 28-char gibberish labels.
NEW v5
FEATURE 25
both_gibberish
Both subdomain AND domain label are gibberish. The ultimate DGA signal — near-100% phishing confidence.
NEW v5

How the Model Evolved

Every real-world bug report made the model smarter. Here's the complete improvement history.

// MODEL v1 — 12 FEATURES
Initial Release
Basic structural features: url_length, dot_count, is_https, has_hyphen, etc. Trained on 12,000 URLs. Caught classic phishing patterns but missed modern attacks.
12 features 12k training URLs
// MODEL v2 — 20 FEATURES
Bug: deficryptowallets.com missed
ESET caught it, PhishGuard didn't. The URL used HTTPS and had no hyphens — all structural features were clean. Added semantic features: suspicious keywords in domain, brand detection, free TLD check. Also rebuilt dataset to 208,000 URLs.
MISSED: crypto drainer domains FIX: suspicious_kw_in_domain, free_tld, brand_in_domain
// MODEL v3 — WHITELIST ADDED
Bug: Udemy.com false positive
Long UTM tracking URLs (utm_campaign=Brand-Udemy...) triggered high query_length and special_char_count. Fixed by adding a trusted domain whitelist — 500+ sites bypass ML entirely. Also tightened suspicious_kw_in_path to use full phrases not single words.
MISSED: legit UTM params = false positive FIX: 500-domain whitelist, strict path phrases
// MODEL v5 — 22 FEATURES
Bug: ourlzllc.com (HTTPS) missed
Fake crypto exchange using HTTPS with a gibberish domain. is_https=1 was overriding the randomness signal. Added domain entropy (Shannon information theory) and is_random_domain flag. Generated 8,000 HTTPS random-domain phishing examples to break the "HTTPS = safe" bias.
MISSED: HTTPS + gibberish domain = safe (wrong) FIX: domain_entropy, is_random_domain, 8k HTTPS phishing examples
// MODEL v6 — 25 FEATURES (CURRENT)
Bug: DGA double-gibberish domain missed
servcaccntwebappaoiuhyswerdg.dtuiertgdfhfgdj.com — both subdomain (28 chars) AND domain were random gibberish. Added 3 final features: subdomain_is_gibberish, longest_label_len (now the #1 most important feature at 25%), and both_gibberish flag. Generated 10,000 DGA-style training examples.
MISSED: DGA subdomain + domain = safe (wrong) FIX: longest_label_len (#1 feature!), subdomain_is_gibberish, both_gibberish
